## 1. 背景与目标

跨书谱系图在书籍数量大（数百本）时需要**先聚类、再分层展开**，避免一次性渲染全图（需求 §3.6.1、验收 9）。聚类优先级（需求 3.1、验收 9、决策 8）：

1. **用户显式 tag**：用户为书籍设置的初步分类 tag（`books.tags_json`），优先采用；
2. **文件夹继承**：无显式 tag 的书默认继承所在文件夹名（同一文件夹默认同 tag）；
3. **领域自动聚类**：仍无 tag 的书按内容领域自动归类（关键词共现推断），仍无归属的书归入「其他」。

聚类结果用于：谱系图前端聚类筛选 chips、同聚类书之间补「主题相似」低分关联边、以及后续「相关领域书籍入暖画像」的领域判定基础（需求 3.4.9，M9）。

本文档 §1~§8 描述第一版 **pre-classify**（粗略聚类，实时计算）；获得 RAG/Skill 资产后的**精细聚类（post-classify）** 设计见 **§9**（M9 已接入，实现状态见 §9.5）。

## 2. 整体流程

```
书籍集合
   │
   ├─ 有显式 tag？ ──► 簇名 = tags_json[0]（首个 tag）
   │
   ├─ 有文件夹？ ──► 簇名 = 文件夹名
   │
   └─ 都没有 ──► 领域自动聚类（§4）
```

实现入口：`assign_clusters(db, books=None) -> dict[int, str]`（book_id → 簇名），由
`global_graph_payload`（全局谱系序列化）与 `compute_cross_book_graph`（同簇补边）调用。

## 3. 前置：关键词抽取与书籍语料

### 3.1 书籍语料 `book_corpus(book)`

参与聚类的文本按优先级拼接：

- 书名 + 作者；
- 每个章节的标题与正文（`chapters.content_text`，适用于 md/txt/epub 等文本型书籍）；
- **PDF 统一按页处理**：PDF 章节正文为空，补充书籍目录下 `local_text/page_XXX.txt`（导入时由 PyMuPDF `page.get_text()` 落盘的按页本地抽取文本，仅作检索/图谱语料，不用于正文展示）。

### 3.2 关键词抽取 `extract_keywords(text, top_n=80)`

无分词依赖的轻量抽取：

- **中文**：用 `[\u4e00-\u9fff]+` 提取连续中文字符串，按**滑动二元组**切分（如「泛函分析」→ `泛函`、`函分`、`分析`）；
- **英文**：用 `[A-Za-z][A-Za-z\-]{2,}` 提取长度 ≥ 3 的英文词（小写化）；
- **停用词过滤**：`_STOPWORDS`（常见中文虚词/高频词 + 常见英文虚词）；
- **权重 = 词频**，最终取频次最高的前 `top_n` 个词返回 `{词: 词频}`。

领域聚类时 `top_n=40`（只取高频词，降低噪声）。

## 4. 领域自动聚类算法（贪心成簇 + 相似吸收）

对既无 tag 也无文件夹的书执行：

```
遍历每本未归类书 b（按 id 升序）成簇（吸收）：
  若 b 的关键词为空 → 簇名 = 「其他」

  吸收相似书：遍历其余未归类书 other：
    公共词 = b 的关键词 ∩ other 的关键词
    若 公共词非空 且 Σ 词频 min(b[词], other[词]) ≥ 2：
      → 与 b 归入同一组（group），不再加「#书id」标点后缀

成簇完成后统一命名（与处理顺序无关）：
  对每个组 group：
    候选词 = _domain_candidates(每本书, RAG后验)：章节标题×3 + 清洗后书名×2 + 正文×1 + 后验×5
             （extract_keywords 抽取，剔除 _GENERIC_DOMAIN_TERMS 泛化词：
               定理/定义/证明/方法/理论/概念/教程/讲义/习题/答案/笔记/前言/摘要/引言/目录…）
    簇名   = _pick_domain_name(candidates, group)：覆盖书数优先 → 词频次之
    无候选 → 取组内最高频关键词；仍无 → 「其他」
```

要点：

- **成簇顺序依赖、命名与顺序无关**：吸收过程仍依赖处理顺序（先处理的书的吸收范围决定组成员），但**簇名在成簇后统一按专业术语挑选**，不再由先处理的书的最高频词决定；
- **相似度阈值**：共享关键词的**加权词频和 ≥ 2**（`Σ min(freq_b[t], freq_other[t])`），比「是否共有某个词」更强，能过滤只碰巧共享 1 个泛化词的组合；
- **命名策略（M9 第四轮）**：簇名必须是**领域专业术语**（如「变分」「空间」「概率」），由 `_domain_candidates`（章节标题×3 + 清洗后书名×2 + 正文×1 + RAG 后验×5）产出候选、`_pick_domain_name` 按「覆盖书数优先 → 词频次之」挑选；**剔除 `_GENERIC_DOMAIN_TERMS` 泛化词**（定理/定义/方法/教程/讲义/习题/答案/笔记/前言 等）与作者/元数据噪声（如「茆诗」）；只含汉字/英文字母/数字，无特殊标点；重名关键词的书并入同一簇；**专业术语词库优先（M9 第五轮）**：用户词库（`backend/domain_terms.txt` 上部）命中优先；系统缓存词库作为备选候选参与覆盖书数优先竞争；
- **未命中任何簇**：关键词为空的书（语料不足）归「其他」。

伪代码与源码一一对应，见 `services/graph/clustering.assign_clusters` 后半段。

## 5. 与跨书关联计算的关系

`compute_cross_book_graph(db)` 在计算完关键词共现边后，用 `assign_clusters` 的结果补边：

- 同簇但关键词重叠不足（未建共现边）的两本书，补一条**低分「主题相似」边**（strength=8，原因「同属「XX」领域」）；
- 这样即使两本书文本表层不重叠，只要用户归入同一 tag/文件夹，谱系图也会保留同领域的基础关联。

## 6. 真实数据示例（当前库）

无 tag、无文件夹的 6 本书按领域自动聚类结果（M9 第四轮实测）：

| 簇名 | 书数 | 说明 |
| --- | --- | --- |
| 阅读 | 1 | 高效阅读术 |
| 空间 | 2 | 泛函分析 + 费恩曼物理（关键词高度重叠被吸收） |
| 变分 | 2 | 变分法基础 + 变分学讲义 |
| 概率 | 1 | 概率论与数理统计教程（茆诗松教材笔记） |

领域名全部为**专业术语**：不再出现「定理」（泛化词）或「茆诗」（作者名）等噪声簇名。

给书籍设置 tag（书架批量设 tag）或归入文件夹后，会自动改用 tag/文件夹名聚类，不再依赖领域推断。

## 7. 参数与修改点

| 参数/逻辑 | 位置 | 修改方式 |
| --- | --- | --- |
| 停用词表 | `_STOPWORDS` | 按语料领域增删词 |
| 关键词数量 | `assign_clusters` 中 `top_n=40`；`extract_keywords` 默认 80 | 提高更全、降低更聚焦 |
| 相似吸收阈值 | `sum(min(...)) >= 2` | 提高则簇更少更粗、降低则簇更多更细 |
| 簇命名 | `_pick_domain_name(candidates, group)`（覆盖书数优先 → 词频次之；候选词 `_domain_candidates` 加权：章节×3+书名×2+正文×1+后验×5） | 命名策略改 `_pick_domain_name`；候选权重改 `_domain_candidates`；可叠加 LLM 命名 |
| 泛化词过滤 | `_GENERIC_DOMAIN_TERMS` | 领域命名剔除的泛化/出版元词（定理/定义/证明/方法/理论/概念/教程/讲义/习题/答案/笔记/前言/附录/摘要/引言/目录 等）；按领域增删 |
| 专业术语词库 | `backend/domain_terms.txt`（`settings.domain_terms_file`，与 .env 同级） | 用户可编辑：上部用户区最高优先级；系统缓存区自动追加学习术语（可编辑/删除）；修改即时生效 |
| 重名处理 | 重名关键词书并入同一簇（无标点后缀） | 如需细分可改为 `领域-1/领域-2` 序号（仍避免标点） |


## 8. 局限与后续增强

- **成簇顺序敏感**：吸收过程取决于先处理的书的吸收范围，组成员可能随顺序变化；命名已与顺序解耦（成簇后统一挑专业术语）；后续可改为「先按两两相似度建图，再取连通分量/社区检测（如标签传播）成簇」；
- **阈值固定**：需求 9.1 决策 20 提到「相关领域判定阈值函数形式确定后再定阈值」，当前 `>= 2` 为初值，后续可引入基于画像的阈值函数；
- **无 LLM 参与**：命名当前为规则化统计（候选词加权 + 泛化词过滤，可复现、零成本）；后续可引入 LLM 打分/命名作为修正层（与关联强度「LLM 打分 × 关键词共现」的三者结合方向一致，见需求 3.4.7）；
- **粗略聚类（pre-classify）**：正文/标题级别的领域推断较粗，RAG 资产就绪后的精细聚类（post-classify）见 §9。
- **不持久化**：聚类每次按最新 tag/文件夹/内容实时计算（`graph_built` 仅标记书内图谱），无需额外缓存；若书量大导致慢，可落盘缓存并按「书籍变更」失效。

## 9. 两阶段分类设计（pre-classify / post-classify）

### 9.1 设计动机

第一版聚类（§4）只用书名/章节正文做**粗略**领域推断（pre-classify）。书籍获得
RAG/Skill 资产（读完归档、外部资料直投、跨书图谱联动增改，见需求 3.4.9）后，资产中的
`summary`、`key_points`（带章节/段落出处）、Skill 的 `name/applicable/usage` 是比正文
更浓缩、更准确的**后验信息**，可用于**更精细的聚类（post-classify）**：细化、合并、
迁移簇，并以代表性术语重命名簇。

### 9.2 触发时机

- 书首次获得 RAG/Skill 资产（资产 `version=1`）时；
- 资产被增改（`version+1`：再次阅读结束 / 跨书图谱联动）时；
- 全局谱系图加载时懒校验：该书资产 `updated_at` 晚于上次 `classified_at` → 重算该书归属。

### 9.3 硬约束与优先级

1. 用户显式 tag / 文件夹名**始终优先**（post-classify 不改动用户意图）；
2. 无 tag/文件夹的书：先用 pre-classify 确定初始簇，再按 §9.4 用资产信息修正；
3. 聚类名（tag / 文件夹名 / 关键词）写入前统一经 `services/graph/lexicon.sanitize_cluster_name`
   清洗：只保留汉字 / 英文字母 / 数字与单词间空格，去除特殊标点符号（保存 tag 时同样清洗）；
   **自动生成的领域名还需是专业术语**：经 `_GENERIC_DOMAIN_TERMS` 泛化词过滤与 `_domain_candidates`/`_pick_domain_name` 命名（M9 第四轮，见 §4/§9.4）；用户可在词库文件 `backend/domain_terms.txt` 维护专业术语，命名优先匹配用户词库（M9 第五轮，见 §4/§7）。

### 9.4 post-classify 算法

输入：书 b 的 RAG 资产 `{summary, key_points[], chunks[]}`、Skill 资产 `{skills:[{name, applicable, usage}]}`。

1. **后验特征抽取**：对 `summary + key_points`（必要时并入 skills 的 `name/usage`）执行
   `extract_keywords(top_n=60)`，得到后验关键词集 `Kp`（比正文关键词更聚焦）；
2. **簇内一致性校验**：若 b 与所在簇的「簇代表特征集」重叠 ≥ 阈值 `T_post`（初值 3，
   待决策 20 阈值函数定稿）→ 维持归属，并更新簇代表特征；
3. **簇迁移**：否则与其它簇比较后验重叠，选最高且 ≥ `T_post` 的簇迁入（记录
   `classify_log`：旧簇 → 新簇、触发原因、资产版本）；
4. **簇合并**：若两个簇的簇代表特征重叠 ≥ `T_merge`（初值 5，常量 `T_MERGE=5`）→ 合并进书更多的主簇
   （被并入的书并入主簇成员列表，保证后续重命名/再合并覆盖全部书；原因「后验：共现概念 n 个」）；
5. **簇重命名**：簇名取簇内出现于最多书的后验术语**众数**（**跳过 `_GENERIC_DOMAIN_TERMS` 泛化词**；与现名/其它簇名冲突则跳过，后续可叠加 LLM 命名）；用户词库/系统缓存词库中的术语优先取用。

> 4、5 已实现：`services/graph/clustering.merge_and_rename_clusters(db)`，由 `archive_book_task` 归档成功后触发
> 重命名时跳过 `_GENERIC_DOMAIN_TERMS` 泛化词；post_classify_book 自动新建簇用 `_first_meaningful_term`（后验关键词中第一个非泛化术语）。
> （结果写入 `result["cluster_merge"]`，失败仅回滚不阻塞）；只处理 `classify_source=post` 的书，
> tag/文件夹硬约束不受影响。

### 9.5 持久化与失效

- 落盘（已实现）：`books` 表 `cluster_name / classify_source(tag|folder|pre|post) / classified_at / classify_version`，
  资产 `version` 变化即失效；合并/迁移日志后续可补独立 `graph_clusters` 表。
- 失效：资产 `version` 变化或书籍内容 / tag / 文件夹变更 → 该书聚类条目失效，下次加载谱系时重算。
- 合并/重命名触发：`archive_book_task` 成功后调用 `merge_and_rename_clusters`（当前全量扫描 post 书；
  书量大后改为增量候选对，并把 pre-classify 也改为落盘缓存，避免每次全局加载全量重算）。

### 9.6 与后续能力的关系

- **相关领域入暖画像**（需求 3.4.9）：post-classify 后的簇即「相关领域」的候选集合，
  与跨书关联强度共同构成决策 20 阈值函数的输入；**阈值自动学习（v1.27）**：
  `services/profile_learning.py` 按归档节奏与确认关联边强度低分位学习
  `related_strength`（默认 60，范围 45~60，可手动覆盖）。
- **跨书关联强度**（需求 3.4.7）：簇合并/迁移产生的共现概念回写 RAG（跨书关联条目）
  与 Skill（跨书对比新方法），版本可追溯。**已实现（v1.27）**：
  `services/graph_sync.py` 本地联动存根（`rag.linked_books` 关联条目 + `domain_terms` 术语补水，
  内容未变化不写库不 bump 版本）；`POST /api/graph/sync` 显式 LLM 增量增改
  （`ai/prompts/rag_link.py`，RAG 补跨书条目、Skill 融合新方法、version+1、失败回滚不阻塞），
  更新后自动触发该书 `post_classify_book`（资产版本变化 → 聚类失效重算，属预期行为）。

## 10. 方案选型：词语向量化 vs 文本共现法（已定稿）

> 状态：**已定稿（2026-08-07）**。主路线 = **A + C 组合**（术语归一化与 IDF 加权解决「输入质量」，图 + 社区检测解决「成簇结构」）；B（词语向量化）降级为可选向量辅助信号（feature flag 默认关）；LLM 定位为**离线修正层**（别名生成、簇命名、方向证据抽取、打分增强），不进入聚类主循环，与需求 3.4.7「LLM×共现×人工」三信号框架一致；技术栈 ADR-010 已同步。
> 约束锚点：ADR-010（不引入其他语言）；本地单用户、无 GPU、网络受限（外部下载/调用不可靠）；需求 3.4.7 关联强度 = LLM 打分 × 关键词共现 × 人工标注（三者结合）。

### 10.1 现状锚点

| 环节 | 现状实现 |
| --- | --- |
| 关键词抽取 | `services/graph/keywords.py::extract_keywords`：中文滑动二元组 + 英文词（≥3 字符）、词频、top_n=80（聚类用 40） |
| 领域聚类 | `services/graph/clustering.py`：贪心成簇 + 相似吸收（共享词加权频次 Σmin ≥ 2）、post-classify（RAG 后验 top60、T_post=3、T_merge=5） |
| 跨书关联 | `services/graph/cross_book.py`：关键词共现余弦 + 笔记加权（上限 15）+ LLM 打分增强（MAX_LLM_PAIRS=40） |
| 专业术语 | 用户词库 `backend/domain_terms.txt`（与 .env 同级，可编辑）优先匹配，系统缓存词库备选 |
| 数据规模 | 当前库为少量示例书；目标数百本 |

### 10.2 方案对比

| 维度 | 文本共现法（现状） | 词语向量化（embedding） |
| --- | --- | --- |
| 语义泛化 | 弱：只认词面，同义/近义不同词不关联 | 强：近义、上下位、跨语言同义可捕捉 |
| 可解释性 | 强：可展示共享关键词作为簇依据与谱系边 label | 弱：仅相似度分数，黑盒 |
| 数学/LaTeX 文本 | 可处理：二元组 + 英文词，公式符号自然跳过 | 差：预训练词表基本无 LaTeX/数学符号，OOV 严重（本项目数学书占比高） |
| 用户专业词库 | 天然融合：词面匹配、优先命名 | 需词表对齐：词库词未必有向量，冷启动词失效 |
| 冷启动 | 零成本，导入即可聚类 | 需预下载本地模型（bge-small-zh 约 100MB+）或调 embedding API；网络受限风险高 |
| 计算/存储 | 纯 Python 十几秒级（后台懒构建），无需持久化 | 数百本书 × 每章推理 + 向量落盘（数百维 × 数千条），分钟级 + 数百 MB，需 faiss/sqlite-vec |
| 离线可用 | 完全离线 | API 模式不可用；本地模式需先成功下载权重 |
| 与 LLM 结合 | 已有：LLM 打分增强（enrich_pairs） | 可互补，但多一层成本与不确定性 |

### 10.3 关键洞察（讨论记录）

1. 实际痛点更可能是**术语不统一**而非「聚类不够语义化」：同一概念在不同书里换词表达。最便宜的解法是**术语归一化/别名表**（用户词库扩展 + LLM 辅助归并别名），归一化后再跑共现，等于用「人工 + LLM」构造可解释的语义等价层。
2. 数学文本是 embedding 的重灾区：预训练中文模型对公式/LaTeX 覆盖差，数学书占比越高向量化收益越低。
3. 可解释性联动谱系图需求（显示与哪本书关系密切及原因）：共现法可展示共享术语，向量化只能展示分数。
4. 需求 3.4.7 本为「LLM 打分 × 关键词共现 × 人工标注」三者结合，向量化更适合作为**可选第四信号**而非替换主干。

### 10.4 讨论倾向（未定稿）

- 主干不变：共现法（pre + post-classify），保持零依赖、可解释、离线可用；
- 第一优先增强（低成本高收益）：**术语归一化/别名表**——`domain_terms.txt` 扩展同义词区，LLM 辅助生成别名映射，归一化后再共现，回写暖画像与跨书关联；
- 第二优先（可选、feature flag 默认关）：本地小向量模型（bge 系，需预下载一次）仅作**辅助信号**（如相似度 = 0.6 共现 + 0.4 向量），用于同簇补边与相关领域判定（决策 20 阈值函数输入）；
- 不做：纯向量化替换共现法；embedding API 作为主依赖。

### 10.5 待决策点（后面统一决定）

1. 是否采纳「共现为主 + 术语归一化增强 + 向量可选辅助」？
2. 若做向量辅助：**本地小模型**（需预下载权重）还是**复用已有 LLM API 的 embedding 接口**（网络不稳定）？
3. 是否建立**聚类质量评估集**（当前库可扩到 20~30 本，簇纯度/与人工标注一致率）来量化「共现 vs 共现+向量」差异后再定阈值？
