### 2.1 配置与数据库（`backend/app/core/`）

- `config.py: settings`——全局配置单例（pydantic-settings，读 `.env`）：`app_host/app_port/data_dir/db_url`、AI 接口参数（`ai_base_url/ai_api_key/ai_model/ai_mode/ai_timeout/ai_verify_ssl/ai_enable_body_send/ai_temperature` + 精细参数 `ai_max_tokens/ai_thinking_type/ai_reasoning_effort/ai_top_p/ai_frequency_penalty/ai_presence_penalty/ai_stop`）、多模态视觉参数（`vision_*`，含 `vision_temperature/vision_top_p/vision_frequency_penalty/vision_presence_penalty/vision_enable_thinking/vision_thinking_budget`）。
  - 修改：新增配置项时在 `Settings` 加字段，并在 `backend/.env.example` 同步模板；密钥只放 `.env`，不入库不打印。
- `database.py: init_db()`——首次启动建表（create_all；存量库轻量迁移：`_ensure_columns` 补列 + `_ensure_indexes` 幂等补索引）；连接事件 PRAGMA：WAL / 外键 / `synchronous=NORMAL` / `cache_size=-20000`（20MB）/ `mmap_size=256MB`（性能第一梯队）。
- `database.py: get_db()`——FastAPI 依赖，提供请求级 SQLAlchemy 会话。
- `time.py: utcnow()`——返回 naive UTC 当前时间（兼容 SQLite），替代已弃用的 `datetime.utcnow`。


### 2.2 解析器（`backend/app/parsers/`）

| 函数 | 功能 | 输入 | 输出 |
| --- | --- | --- | --- |
| `parse_book(path, title_hint=None)` | 按扩展名分发 | 文件路径 | `ParsedBook` |
| `split_by_headings(raw, title_fallback, is_heading)` | 公共切章助手（`parsers/_split.py`）：按标题行切分，空章节不占序号，无标题时整本一章 | 全文/标题/标题匹配函数 | `ParsedBook` |
| `parse_markdown(path, title_hint=None)` | MD 按 `#`/`##`/`###` 切章；书名取首个 `#` | 路径 | `ParsedBook` |
| `parse_txt(path, title_hint=None)` | TXT 按「第X章/Chapter N」切章 | 路径 | `ParsedBook` |
| `parse_pdf(path, title_hint=None)` | PDF（含文本型）统一按原始页切章（每页一章，content 为空，`page_index=页号`）；本地抽取文本按页放入 `page_texts`（仅作全文检索索引） | 路径 | `ParsedBook` |
| `parse_epub(path, title_hint=None)` | EPUB 解包提取正文（HTML→文本） | 路径 | `ParsedBook` |

- 使用：`ParsedBook.title/author/chapters[]`，章节为 `ParsedChapter(index, title, content)`；空内容章节不占序号。
- 修改：新增格式在 `parsers/` 下加模块，并在 `parse_book` 注册、`SUPPORTED_EXT` 增加扩展名；解析器内 `title_hint` 用于优先使用原始文件名，不要用落盘临时文件名。


### 2.3 导入服务（`backend/app/services/import_service.py`）

- `import_book_file(db, src_path, filename, title=None, author=None, content_hash=None) -> (Book, task_id)`——**两段式（决策 35）+ 分块流式写盘（性能第一梯队）**：把路由分块写入的暂存文件移入 `data/books/{uuid}{suffix}`（`content_hash` 由路由增量计算传入，未传则 `_sha256_file` 计算）→ 解析 → 建 `Book` + `Chapter` + 封面；PDF 同步段只写 `local_text/` 抽取文本作全文检索索引、**不再渲染页图**（v1.105 审查 B-2：消除双倍渲染）；耗时阶段提交 `import-background` 任务（render 配额）并返回 task_id。
- `import_book(db, file_bytes, ...)`——字节兼容入口（测试/小文件）：写暂存文件后委托 `import_book_file`，走同一落盘链路。
- `_import_background(book_id)`——后台阶段：PDF 页图并发渲染（`render_pdf_pages(workers=page_render_concurrency)`；本地全文索引已由同步段写入、不再重复解析 PDF，v1.105 审查 B-2）→ 跨书图谱增量（`incremental_cross_book_graph`）→ 视觉预提取；进度权重 40/40/20（渲染 0→40 / 图谱 40→80 / 视觉 80→100）。
- 修改：格式校验在 `SUPPORTED_EXT`；文件存储目录由 `settings.data_dir` 控制；`total_chapters` 由解析结果回填；任务内必须用独立 `SessionLocal`（勿复用请求级 db）。

### 2.7 后台任务（`backend/app/tasks/__init__.py`）

- `submit(task_type, task_name, fn, *, quota=None, related_id=None) -> task_id`——**落库**（`tasks` 表，完成保留 7 天 `RETENTION_DAYS`，提交时顺带清理）→ 全局线程池（`TASK_WORKERS`，0=每任务独立线程）→ 同类型配额信号量（text/vision/render，`TASK_QUOTA_*`/`PAGE_RENDER_CONCURRENCY`，0=不限制）。
- `submit_sync(...)`——同步执行版本（测试/调试用，同一套落库/配额/进度逻辑）。
- `update_progress(progress, stage)`——任务函数内上报进度（0~100 + 阶段文案），线程本地路由到当前任务，500ms 节流写库。
- `find_active(task_type, related_id=None, name_prefix=None) -> task_id | None`——查进行中任务（幂等复用，避免重复提交）。
- `mark_interrupted()`——服务启动时调用：遗留 queued/running 任务标记 failed（进程重启中断，防死任务被幂等复用）。
- `get_status(task_id) -> dict` / `list_tasks(task_type=None, status=None, limit=20) -> list[dict]`——状态与列表（`{id,type,name,status,progress,stage,result,error,related_id,created_at,finished_at}`）。
- API：`GET /api/tasks`（列表）、`GET /api/tasks/{id}`（状态）。
- 修改：新增任务类型在 `_quota_for` 登记配额来源；任务函数内严禁复用请求级 Session（用 `SessionLocal()`）；SQLite 写冲突由 `_db_write` 短事务重试兜底。

### 3.7 一键启动（`start.bat`）

- 双击根目录 `start.bat`：检查依赖（node / 后端 venv / 前端 node_modules）→ 后台窗口启动后端（8321）与前端（5173）→ 自动打开浏览器；启动完成后**主窗口保持等待，按任意键即停止前后端服务并退出**（直接关闭窗口则服务继续运行）。
- **手动停止 / 重启（v1.88）**：`start.bat stop` 按端口（8321/5173）定位监听 PID 并 `taskkill /F /T` 结束进程树，未运行时幂等提示；`start.bat restart` = 先停止再重新启动（等价于 stop 后重新运行 start.bat）。
- **端口占用检测（v1.66）**：启动前用 `netstat` 检测 8321/5173，已在运行则提示「已在运行」并跳过，避免重复启动报 `WinError 10048`（端口只能绑定一次）。
- **运行环境限制（v1.106）**：后端必须在**非受限网络环境**启动（普通 cmd/PowerShell 双击 start.bat 即可）；若由受限/沙盒环境（如 Codex/IDE 内置终端）拉起，出站 TCP 会被拦截，LLM API 全部报 `WinError 10013`（表现为聊天/总结/脑图/视觉提取等一切外联失败，但本地 8321 访问正常）。修复方法：`start.bat stop` 停止后，在普通终端重新 `start.bat`。
- 前端启动命令解析顺序（避免系统 PATH 无 pnpm 时报「不是内部或外部命令」）：PATH 上的 `pnpm` → `node node_modules\vite\bin\vite.js`（node 兜底，离线可用）→ `%LOCALAPPDATA%\pnpm\pnpm.cmd` → Codex 运行时 pnpm。
- 修改：端口改批处理内 `--port`；前端如需用 `vite preview`，改 `:front_vite` 分支里的启动命令。

### 13.2 性能优化（M10）

- **后端页图目标宽度缓存**：`parsers/pdf.py` `pdf_page_target_width` 委托 `_target_width_cached`（`functools.lru_cache(maxsize=4096)`，按 `(文件路径, 页号)` 缓存），避免每次页图请求重新打开 PDF；书籍导入后 PDF 不变，页图仅在分辨率不足时按需升级，缓存安全。
- **页图缓存头**：`GET /api/books/{id}/pages/{page_index}` 响应 `Cache-Control: private, max-age=600`（页图不可变，10 分钟内翻页走浏览器缓存，不再每次全量重传）。
- **前端相邻页预加载**：`ReaderView.vue` PDF 页模式渲染 `.page-preload` 隐藏 img（`position: absolute; left: -9999px`）预热当前页 ±1 页浏览器缓存，翻页更跟手。
- **vite vendor 分包**：`vite.config.ts` `manualChunks` 拆分 `vendor-vue / vendor-element / vendor-echarts / vendor-markdown`；echarts 仅图谱/脑图路由按需加载；ReaderView 主 chunk 189KB → 56KB。

### 13.4 性能优化第一梯队（2026-08-04，docs/性能优化路径.md §4）

- **SQLite PRAGMA 调优**（`core/database.py` 连接事件）：`synchronous=NORMAL`（WAL 下安全，降低写盘频率）、`cache_size=-20000`（页缓存 20MB）、`mmap_size=268435456`（256MB）；WAL 与外键保留。
- **外键/热点查询索引**：模型外键列 `index=True` + `_ensure_indexes()` 幂等 `CREATE INDEX IF NOT EXISTS`（存量库启动即补，新库 create_all 直建）；组合索引 `ix_book_assets_book_kind`、`ix_bookmarks_book_created`、`ix_reading_logs_book_updated`（book_id, updated_at DESC，v1.104）、`ix_user_profiles_layer_dim`（layer, dimension，v1.104）；覆盖 chapters / notes / bookmarks / chat_messages / book_relations / knowledge_points / kp_relations / reading_logs / tasks 等热点查询列。
- **关键词内容寻址缓存**（`services/graph/keywords.py`）：`extract_keywords` 按文本 sha256 缓存（前 200 高频词、`_KEYWORD_CACHE_MAX=2048` 溢出整体清空），`book_keywords(book, top_n)` 整书入口；聚类 / 跨书相关度 / 推荐 / 画像全部共享；`clear_keyword_cache()` 供测试与手动重置。
- **聚类结果落盘缓存**（`services/graph/clustering.py`）：`data/cache/graph_clusters.json`（原子写：先 .tmp 再替换）；缓存键为**群体签名**（全书库每书判定签名排序哈希，覆盖内容 hash / 标题作者 / tag / 文件夹名 / 资产版本），任一书变化自动失效重算；`assign_clusters` 全命中时直接返回，打开谱系图不再全量重算与回写 DB。
- **上传分块流式写盘**（`api/routes/books.py` + `import_service.py`）：路由按 1MB 分块读 `UploadFile` 写入 `data/uploads/{uuid}.upload`，边写边算 sha256；`import_book_file` 移入书籍目录后解析入库，暂存文件自动清理。
- 修改：缓存容量/路径改 `keywords._KEYWORD_CACHE_MAX` 与 `clustering._cluster_cache_path()`；新增热点查询先补 `_INDEX_DDL` 与模型 `index=True`；测试见 `tests/test_perf_tier1.py`（6 项）。


### 13.5 性能优化第二/三梯队（2026-08-04，docs/性能优化路径.md §4/§7）

- **会话历史裁剪**（`repositories/chat.py::trim_history`）：`persist_chat` 写入后自动裁剪到最近 `chat_history_limit` 条（默认 200，`.env` 可配，0=不限制）；用户可手动清空（`DELETE /chat/messages`）。修改：调 `settings.chat_history_limit`。
- **LLM 结果缓存**（`models/llm_cache.py` + `services/llm_cache.py`）：内容寻址（book_id + kind + 输入指纹 sha256 前 16 位），TTL `llm_cache_ttl_days`（默认 30 天）、容量 `llm_cache_max_entries`（默认 300 条，超限删最旧，0=关闭）。入口：脑图 `mindmap_service.generate_mindmap`（命中返回 `cached=true`）与预设模式问答（chat 路由：命中直接回放 `end.cached=true` 并落历史，未命中流结束后写入缓存）。缓存键覆盖章节内容指纹 + 选区/焦点 + 隐私开关 + 页模式，任一变化自动换键；删除书籍级联清缓存。修改：键构造见 `chat_service.build_mode_cache_key` / `mindmap_service.generate_mindmap`，容量/TTL 在 `.env`。
- **FTS5 全书搜索**（`core/database.py::_ensure_fts` + `services/search_service.py` + `repositories/search.py` + `GET /api/books/search?q=`；v1.104 审查 A-4：FTS/LIKE 原生 SQL 下沉 `repositories/search.py`，服务层只做拆词/摘要/编排）：trigram 分词（中文 3 字符及以上子串命中），AFTER INSERT/UPDATE/DELETE 触发器与 chapters 同步，存量库首次启用自动回填；短词（1-2 字符）回退 LIKE 扫描；`fts_search_enabled` 开关（默认开，关闭时不建索引、接口返回空）。修改：分词器/回填策略在 `_ensure_fts`，查询/摘要逻辑在 `search_service`。
- 测试：`tests/test_perf_tier2.py`（8 项：历史裁剪、缓存命中/TTL/容量淘汰/清理、FTS 命中与删除联动、模式缓存键、搜索路由、模式问答二次命中缓存）；后端全量 189 pytest + ruff 全绿。

### 20.2 关键数据流三条（代码调研 2026-08-05）

```text
导入链路：POST 上传 → 同步阶段（格式校验 → 内容 hash 去重 → move 至 data/books/<file_id>/ → parse 章节入库 → 封面）秒回
  → 后台 import-background（页图并发渲染 → 扫描版判定 → vision 页文本提取 → 进度上报）
```

```text
AI 对话链路：POST chat → rag_router 两级挑选（LLM 挑选器 + 规则降级，session 缓存 60min）
  → 上下文组装（段落编号正文/RAG 片段/页窗口/多轮历史）→ build_client SSE 流式
  → 滚动落库（stream_key，1.5s 节流）→ 结束后裁剪历史（200 条）+ 可缓存模式写 llm_caches
```

```text
图谱构建链路：关键词抽取（中文二元组+英文词+领域词库）→ 书内图谱（章节/重要段落/用户标记三层 + 重建）
  → 跨书谱系（共现余弦 + 笔记加权 + LLM 打分 ≤40 对，全量/增量两入口）
  → 两阶段聚类（签名落盘 graph_clusters.json）→ 归档/删书触发 graph_sync 联动增改
```


### 20.3 核心约定（代码调研 2026-08-05）

- **路径约定**：`data/books/<file_id>/` 每书独立子目录（原文件 + cover.jpg + pages/page_XXX.jpg + local_text/ + page_text/ + annotations/）；`data/llmnotebook.db`；`domain_terms.txt` 与 backend/ 同级。
- **命名约定**：会话键 `book:{book_id}[:mode]`；Setting 键点号命名空间（`profile.*`）；索引 `ix_<table>_<column>`；资产 kind ∈ {rag, skill}；任务 type ∈ {text, vision, render, generic}。
- **迁移约定**：create_all 建新表 + `_ensure_columns` 手工 ALTER 清单补列 + `_ensure_indexes` 幂等补索引 + FTS5 触发器维护；alembic 已声明依赖但未启用（新增列必须在 `_ensure_columns` 登记）。
- **时间约定**：DB 一律 `core/time.utcnow`（recommendation/profile_learning/tasks 仍有本地 `datetime.now()` 混用残留，新增代码勿效仿）。


### 20.4 已知局限性（客观陈述，代码调研 2026-08-05）

1. 单用户本地应用假设，无鉴权、无多租户维度。
2. SQLite 单写者：分钟级长事务（全量图谱重建）会阻塞全局写入。
3. 进程内缓存（rag_router session、lexicon、keywords）重启即失效，且部分无容量上限。
4. LLM 功能完全依赖外部 API 配置，`.env` 缺 `AI_API_KEY` 时对话/图谱 LLM 环节直接报错（有规则降级路径的仅 rag_router）。
5. GBK 等非 UTF-8 文本静默乱码；超大文件无上限校验。
6. 导入链路、搜索服务无测试覆盖。
