## 1. 背景与目标

异步/并行改造解决「等待与阻塞」；本文档解决「**计算重复与数据放大**」——数据量增长（数百本书、数万笔记/对话）后，无缓存的重复计算与缺失索引会成为主要瓶颈。

目标：

1. 消除重复计算：关键词抽取、聚类、章节解析、LLM 结果；
2. 补齐数据层基础：外键索引、SQLite PRAGMA、历史数据清理策略；
3. 减负前端：路由懒加载、封面懒加载、长列表虚拟滚动；
4. 检索架构增强（需决策）：FTS5 全文搜索、本地向量检索；
5. 全程遵守 ADR-010：不引入新语言 / 新服务。

## 2. 已核实问题（代码事实）

| # | 问题 | 代码事实 | 影响 |
| --- | --- | --- | --- |
| 1 | **外键索引缺失** | 各模型外键均未建 `index=True`（仅 `chat_messages.session_id` 有索引）：`chapters.book_id`、`notes.book_id/chapter_id`、`bookmarks`、`assets.book_id`、`BookRelation.book_a/b_id`、`knowledge_points`、`kp_relations` 等 | 按书查询全表扫描；书/笔记/消息多时列表、图谱、画像全链路变慢 |
| 2 | **上传整读内存** | `books.py upload_book`：`data = await file.read()`（决策 32 设计为分块流式写盘，实现未跟上） | 大 PDF 导入内存峰值高 |
| 3 | **关键词重复抽取** | `extract_keywords(book_corpus(book))` 在聚类（每次打开谱系图全量重算）、相关度判定、推荐、画像迁移、图谱增量、联动存根各自独立重跑，无缓存 | 每开一次谱系图全量分词；多处重复计算 |

## 3. 优化路径全景

| 维度 | 路径 | 收益 | 成本 | 依赖 / 决策点 |
| --- | --- | --- | --- | --- |
| 数据层 | 外键索引补齐（alembic 迁移） | 高 | 低 | 无 |
| 数据层 | SQLite PRAGMA 调优：`synchronous=NORMAL` / `cache_size` / `mmap_size`（WAL 已启用） | 中 | 低 | 无 |
| 数据层 | 聊天历史 / 会话清理与归档策略（当前无限增长） | 中 | 低 | 决策：保留期限 / 归档方式 |
| 计算缓存 | 关键词缓存：按 `book.content_hash` 失效，聚类 / 相关度 / 推荐 / 画像共享 | 高 | 低 | 无 |
| 计算缓存 | 聚类结果缓存：tag / 文件夹 / 内容变更即失效的落盘缓存（不再每次打开谱系图重算） | 高 | 低 | 无 |
| 计算缓存 | 跨书共现倒排索引（词 → 书集合，只算共享词的书对） | 中高 | 中 | 数百本时启用 |
| 计算缓存 | LLM 结果缓存：脑图 / 解读 / 概论按「章节 + 参数」缓存 | 中高 | 中 | 决策：缓存键与失效（内容变更 / 资产版本） |
| LLM | 对话历史滚动摘要压缩（早于 6~10 轮的历史摘要化） | 中 | 中 | 与决策 30 会话注入协同 |
| LLM | 任务分级模型：简单任务用便宜模型（挑选 / 分类），深度解读用主模型 | 中 | 低 | 与决策 34 挑选器衔接 |
| 存储 | 上传分块流式写盘（修复整读） | 中 | 低 | 决策 32 落地时一并 |
| 存储 | 书架封面懒加载 | 低中 | 低 | 无 |
| 存储 | 页图小文件策略（保持文件系统 vs SQLite 页图库） | 低中 | 中 | 决策：默认保持文件系统（推荐） |
| 前端 | 路由级懒加载（views 按路由 split，当前仅 vendor 分包） | 中 | 低 | 无 |
| 前端 | 章节正文解析缓存（`splitBlocks` 每次切章全量解析） | 中 | 低 | 无 |
| 前端 | 虚拟滚动（书架 / 对话历史 / 资产列表） | 中 | 中 | 书/数据多时启用 |
| 前端 | ECharts 大图渐进渲染（数百节点谱系图） | 低中 | 中 | 数百节点时 |
| 检索 | SQLite FTS5 全文搜索：`local_text` 已落盘但未建索引、无搜索 API | 中高 | 中 | 决策：是否提供全书内容搜索 |
| 检索 | 本地向量检索（sqlite-vec / faiss）：RAG 线性扫描 → 向量近邻 | 高（RAG / 聚类） | 高 | 决策：与聚类 §10、网络受限环境一起定 |

## 5. 与异步/并行改造计划的关系

- **互补不重叠**：异步/并行解决「等待与阻塞」；本路径解决「计算重复与数据放大」；
- **同批合并**：第一梯队与异步 Phase 1 合并执行（索引迁移 + 任务系统 + 导入改造一次做完，避免两次迁移）；
- **共享决策点**：上传流式写盘随决策 32 落地；向量检索与聚类 §10、RAG 挑选（决策 34）一起定；任务分级模型与挑选器配置（9.3.1）衔接。
- **落地情况（2026-08-04）**：第一梯队与前端并行收尾同批实施完成；第二/三梯队同日实施完成——决策 1（聊天历史只留最近 N 条）、2（LLM 结果缓存）、3（FTS5 全书搜索）、4（页图保持文件系统）均已定稿落地；「任务分级模型」随决策 34 挑选器待定；「本地向量检索」为开放项。

## 6. 验收与评估

1. 索引：`EXPLAIN QUERY PLAN` 关键查询（按书章节 / 笔记 / 消息 / 资产 / 图谱边）走索引；数据量翻倍后列表与图谱接口耗时曲线平缓；
2. 缓存：重复打开谱系图 / 相关度计算 / 推荐耗时不随访问次数增长（命中缓存）；内容 / tag / 文件夹变更后自动失效；
3. 前端：首屏 bundle 体积下降；书架滚动与切章体感改善；
4. 回归：后端 pytest 全绿、ruff 全绿、vue-tsc + vite build 通过；
5. 第一梯队专项（2026-08-04）：`tests/test_perf_tier1.py` 6 项——PRAGMA 生效、索引清单齐备、关键词缓存命中/清空一致、聚类缓存命中与 tag 变更失效、上传流式多块无残留且 sha256 正确；后端 181 项全绿。
6. 第二/三梯队专项（2026-08-04）：`tests/test_perf_tier2.py` 8 项——会话历史裁剪（200 封顶 / 0=不限）、LLM 缓存命中 / TTL 过期 / 容量淘汰最旧 / 按书与全量清理、FTS5 中文子串命中与删除章节联动清理、短词 LIKE 回退、搜索路由、预设模式问答二次命中缓存（`cached=true` 且不再调用 LLM）；后端 189 项全绿。
