## 0. 背景与目标

- 当前部署形态：本地单用户 Web 应用（Vue3 + Vite 前端 / FastAPI 后端 / SQLite / 本地文件系统），启动依赖 `start.bat`（Windows 专属，前后端双进程）。
- 后续目标：移植**桌面端**与**移动端**。
- 本轮范围：**只做「约束级预留冗余」，不启动任何打包/脚手架工程**（Tauri/Electron/Capacitor 均不动）。打包前置条件：A~F 风险修复计划完成并全绿（避免并发改造与移植叠加的回归风险，§2.3 Q3）。

## 1. 现状盘点

### 1.1 移植友好项（已具备）

| 项 | 现状 | 说明 |
|---|---|---|
| 前端纯 Web | 对 `window`/`document` 依赖仅 3 处（主题 `graphEdges.ts:8`、可见性 `historyReplaceDefuse.ts:20`、任务事件 `task.ts:9`） | 可嵌入任意 WebView，零重写 |
| 前后端分离 | 前端全部走 REST API，不直连文件系统 | 桌面/移动 App 可直接复用同一 API 契约 |
| 数据单文件 | SQLite 单文件 + `data_dir` 可配置（`config.py:14`） | 数据层可整体搬移/导出 |
| 解析重依赖收敛 | PyMuPDF / ebooklib / markdown 解析均在服务端 | 客户端无需携带 |

### 1.2 阻碍点（需预埋）

| # | 阻碍 | 位置 | 影响 |
|---|---|---|---|
| 1 | 启动形态 Windows 专属、双进程 | `start.bat` | 桌面打包需「宿主拉起后端进程」抽象 |
| 2 | 后端仅绑定 `127.0.0.1`、无 CORS 配置 | `start.bat` / `app.main` | 移动端远程访问不可行 |
| 3 | 桌面语义交互（拖拽、滚轮缩放、悬停、指针涂鸦、快捷键）散落组件 | `ReaderView.vue`（719 行）等 | 移动端触摸适配困难 |
| 4 | 大组件未按需加载 | `ReaderView.vue`、`PageDoodleCanvas.vue`（430 行）等 | 移动端低端机加载/内存压力 |
| 5 | SSE 流式无重连/断点语义 | `api/chat.ts`、`chat_service.py` | 移动端弱网体验差 |

## 2. 移植形态与决策点

## 3. 预留冗余分层措施（全部为低成本约束级）

### L-API 契约层
- 现状：前端已全走 REST API。
- 约束：**不新增**任何前端直连文件系统 / 直读本地路径的代码；保留 OpenAPI 导出能力供未来 App 客户端复用。

### L-服务层
- `HOST` / `PORT` / `CORS_ORIGINS` 进 `.env`（默认 `127.0.0.1` 不变；`0.0.0.0` 为可选开关，含安全提示）。
- 启动方式从 `start.bat` 抽象为「`uvicorn app.main:app` 可被任意宿主拉起」（已满足，补文档说明）。
- 桌面打包时后端进程由宿主拉起（Tauri sidecar 或子进程），API 地址由环境注入前端。

### L-存储层
- 全部文件读写（书籍文件、页图、页缓存、资产附件、词库）已收敛在 service 层。
- 动作：审计登记「存储访问点清单」（文件:行号）写入使用手册；明确未来移动端只替换该层（沙盒文件系统）。

### L-前端层
- 桌面专属交互（拖拽排序、滚轮缩放、悬停菜单、指针涂鸦、快捷键）收敛进 composable。
- `ReaderView.vue` 等大组件拆分子组件（移动端按需加载）。
- 布局加响应式断点：≥1280 三栏 / 768~1279 双栏 / <768 单栏抽屉。

### L-传输层
- SSE 流式补「断线重连 + 终态兜底落库」语义（并入 C 计划 C2/C3 一起做）。
- 页图加 `?w=` 宽度参数（移动端流量优化；即风险清单 D5，**提升为推荐做**）。

### L-依赖层
- 解析类重依赖（PyMuPDF 等）保持服务端。
- **不预埋** WebAssembly PDF 解析（YAGNI，留决策点）。
