### 2.9 前端骨架（`frontend/`）

- 技术栈：Vue 3.5 + TypeScript（严格模式）+ Vite 6 + Element Plus + Pinia + Vue Router 4 + ECharts 5 + axios + markdown-it / KaTeX / DOMPurify。

**目录结构**

| 文件 | 说明 |
| --- | --- |
| `src/main.ts` | 入口：注册 Pinia / Router / Element Plus，引入全局主题 |
| `src/router/index.ts` | 路由：`/`（书架主页）、`/reader/:bookId`（三栏阅读）、`/graph` / `/settings` / `/profile`（占位页） |
| `src/api/client.ts` | axios 实例 + 统一 `{code, message, data}` 解包与错误处理 |
| `src/api/books.ts` | 书籍/文件夹 API 封装 |
| `src/types.ts` | 前端类型定义（Book / Folder 等） |
| `src/stores/book.ts` | 书架状态（Pinia） |
| `src/views/` | 五个页面组件：`HomeView`（左近期阅读右书架）、`ReaderView`（三栏：左 25% 书架+目录 / 中 45% 正文 / 右 30% AI 助手）、`GraphView`、`SettingsView`、`ProfileView` |
| `src/styles/theme.css` | 全局主题样式 |

**构建与运行（已验证）**
```bash
pnpm install          # pnpm 11：allowBuilds 配置见 frontend/pnpm-workspace.yaml
pnpm dev              # 开发服务器 http://127.0.0.1:5173，代理 /api → http://127.0.0.1:8321
pnpm build            # vue-tsc --noEmit && vite build → dist/（已通过，EXITCODE=0）
```
- pnpm 11 不再读取 `package.json#pnpm` 字段，构建脚本与依赖放行统一在 `frontend/pnpm-workspace.yaml`（`allowBuilds: esbuild/vue-demi`、`verifyDepsBeforeRun: false`）。
- 冒烟验证：后端启动在 `8321` 后，`pnpm dev` 可访问书架主页（近期阅读 + 书架，数据来自 `/api/books`）与 `/reader/:bookId` 三栏布局。

**如何修改**
- 新增页面：在 `src/views/` 新建组件并在 `src/router/index.ts` 注册路由。
- 新增接口：在 `src/api/` 下按 `client.ts` 的解包约定扩展，禁止在组件内直接拼 axios。
- M3 任务：在 `ReaderView` 接入章节正文渲染、进度记录、笔记与「不理解」标记；Markdown/LaTeX 渲染按 `技术栈规范.md` §4.6。
- v1.107（EPUB 方案 A）：`ReaderView` 新增 **epub_render 分支**——`book.format === 'epub'` 时不再按段落切块，章节正文（消毒后 HTML）经 `DOMPurify.sanitize` 后 `v-html` 渲染到 `.epub-body`（图片走 `GET /api/books/{id}/media/{filename}` 白名单端点，max-width 100%）；划词菜单（高亮/批注/思考/不理解/AI 解释/脑图）沿用全局选择事件，逐段 hover 快捷按钮仅对 md/txt 生效（EPUB 排版模式下请用划词菜单）。

### 3.13 书架排序/搜索/标签（第 16 轮任务产出，HomeView 打磨）

#### 3.13.1 后端能力（`books.py` 路由 + `repositories/books.py`）

- `Book.position`（INTEGER，默认 0）：书架排序位。新书导入自动追加到末尾（全局最大位 + 1，`create_book_with_chapters`）；旧库由 `database._ensure_columns` ALTER 补齐。
- `GET /api/books?q=关键词`：搜索书名/作者/标签（`or_(title.contains, author.contains, tags_json.contains)`），可与 `folder_id` 组合。
- `POST /api/books/reorder`：body `{ordered_ids: [书id...]}`，按期望顺序批量重排（position 1..N，未知 id 忽略），供拖拽换位持久化。
- `PATCH /api/books/{id}` 支持 `position` 单本调整。

#### 3.13.2 前端（`frontend/src/views/HomeView.vue` + `src/api/books.ts`）

- **布局**：书架工具栏（搜索框 + 标签下拉筛选 + 导入按钮）sticky 置顶；卡片显示封面/书名/标签 chips/阅读进度三段式；悬停显示操作按钮（🏷 编辑标签、🗑 删除）。
- **拖拽换位**：卡片 `draggable`，`dragstart` 记录拖拽书、`dragover/drop` 高亮并交换目标书（按 id 在全量列表内互换），随后 `reorderBooks(全量顺序)` 持久化；失败回滚重取列表。
- **手动标签**：卡片 🏷 弹层 `el-select multiple filterable allow-create`（候选 = 全部书的标签去重），保存走 `updateBook(id, {tags})`（后端去空白/去重，保留用户输入原样，E2E M-2 2026-08-11）；点击卡片标签 chip 直接切换该标签筛选。
- **搜索/筛选**：`searchQuery` 对书名/作者/标签做本地过滤；`activeTag` 标签筛选；二者可组合，无结果时显示空态提示。

#### 3.13.3 冒烟要点

1. 导入 3 本书 → 书架按导入顺序排列（position 1/2/3）。
2. 拖动第 3 本到第 1 本位置 → 释放后顺序更新并持久化（刷新页面仍在）。
3. 卡片 🏷 添加「数学」「概率」→ 保存后卡片显示标签；顶部标签下拉出现新标签；点击标签筛选只剩对应书。
4. 搜索框输入书名/作者/标签关键词 → 列表即时过滤；清空恢复。
5. 回归：`pytest`（125 项）+ ruff + vue-tsc + vite build。

#### 3.14.2 标签编辑器 bug 修复（`frontend/src/views/HomeView.vue`）

测试发现并修复 3 个问题：

1. **共享 `tagPopVisible` 导致一次点击弹出全部弹层**：`v-for` 内 6 个 `el-popover` 共用一个 `v-model:visible`，点任一 🏷 会同时打开全部 6 个弹层，且 `@show` 依次触发使 `tagEditBook` 指向最后一本书（保存到错误的书）。
   - 修复：改为 `tagEditId = ref<number|null>` 按书籍 id 独立控制可见性（`:visible="tagEditId === b.id"`）。
2. **保存目标错乱**：改为按钮 `@click.stop="toggleTagEdit(b)"` 在点击时显式 `prepareTagEdit(b)`（设置 `tagEditBook`/`tagDraft`），不再依赖受控 `:visible` 下不可靠的 `@show` 事件。
3. **弹层被下拉/点击关闭**：`el-select` 下拉默认 teleport 到 body，点击「创建标签」选项会被 popover 判为外部点击而关闭编辑；同时 teleport 的下拉会遮挡「保存/取消」按钮。
   - 修复：`trigger="manual"` 完全受控显隐（取消/保存按钮负责关闭）；`el-select :teleported="false"` 使下拉渲染在弹层内；select 与操作按钮之间加 `.tag-select-spacer`（44px）占位，避免空下拉遮挡按钮。

修复后实测全流程（含中文标签）：点 🏷 → 仅打开 1 个弹层 → 输入新标签 → 点击创建选项 → 点「保存」→ 后端 `tags` 落库（`["泛函分析"]`）→ 卡片显示标签 chip → 提示「标签已更新」；「取消」正常关闭。

### 3.15 书架文件夹桌面式布局（D8）与文本书工具栏宽度调节（D9，2026-08-11）

> 来源：E2E 实测确认「书架无文件夹 UI」（后端 folders API 已有、前端零引用）后实现；用户定稿为「文件夹与书放一起，类似电脑桌面的布局」。

#### 3.15.1 文件夹（桌面式书架）

- **布局**：`HomeView.vue` 书架网格中，文件夹以 `folder-card` 与书卡片混排（📁 图标 + 名称 + 直接书数量），进入文件夹后显示其书籍与子文件夹，面包屑（`folder-crumbs`）提供「全部书籍 / 父级」导航，空文件夹也可返回。
- **交互**：
  - 工具栏「📁 新建文件夹」——在当前文件夹（根视图=根文件夹）下创建；文件夹卡片 hover 的 ＋/✏️/🗑 分别新建子文件夹、重命名、删除（确认框提示书籍转未归类）。
  - 书卡片「📁」按钮弹出移动菜单（未归类 + 文件夹树拍平列表，缩进表示层级）；拖拽书到文件夹卡片也可移动。
  - 「☑ 批量」模式：卡片出现勾选框，顶部操作条「移动到文件夹（弹层选择）/ 批量设 tag（追加，逗号/空格分隔）/ 退出批量」。
- **视图过滤**：根视图显示未归类书 + 根文件夹；文件夹视图显示 `folder_id == id` 的书 + `parent_id == id` 的子文件夹；搜索/标签筛选在视图内生效（文件夹按名称匹配）。
- **API**：新增 `frontend/src/api/folders.ts`（`listFolders` / `createFolder` / `renameFolder` / `deleteFolder`，对应 `GET/POST /api/folders`、`PATCH/DELETE /api/folders/{id}`）；`types.ts` 新增 `FolderItem`。
- **后端配套修复**：`repositories/books.py::update_book` 的 `folder_id` 参数改哨兵语义（`_UNSET`），此前 `None` 被当作「未传」导致无法把书移出文件夹；现 PATCH `folder_id: null` 正确移出（回归测试 `test_patch_book_folder_id_null_moves_out`）。

#### 3.15.2 文本书（MD/EPUB）工具栏页码与宽度调节（D9）

- `ReaderView.vue` 非页模式工具栏在章节标题前显示「第 x/共 x 章」（`page-indicator`），右侧新增宽度调节（`text-zoombar`：－/＋，640~1200px，默认 860px，显示当前 px）。
- 正文容器 `reading-scroll` 应用 `maxWidth + margin: 0 auto`（`textBodyStyle`），仅文本书生效；PDF 页模式不受影响。

### 7.6 LLM 输出数学公式定界符归一化（`src/utils/math.ts`）

LLM 常用裸括号/方括号写公式（如 `(\operatorname{ext}(K))`、独占一行的 `[ ... ]`），
标准渲染管线只认 `$...$` / `$$...$$`，导致公式原样输出。新增归一化工具：

| 函数 | 说明 |
| --- | --- |
| `normalizeMath(src)` | 组合入口；代码围栏内不转换 |
| `normalizeBlockBrackets(src)` | 独占一行且含 LaTeX 命令的 `[ ... ]` → `$$...$$` |
| `normalizeDelimiters(src)` | `\(...\)` / `\[...\]` → `$...$` / `$$...$$` |
| `normalizeInlineParens(src)` | 含 LaTeX 命令的裸 `( ... )`（支持嵌套）→ `$...$`；跳过已定界公式 |
| `normalizeBareMath(src)` | 裸 Unicode/LaTeX 数学（如 `Λ^n V`、`λ−1`、`A∈R`）→ `$...$`；跳过已定界公式，仅包裹含上标/下标或 ≥2 个数学相关字符且括号/花括号配对的短片段（v1.75） |

- 使用：`MdRender.vue` 在 protectMath 每个非代码围栏段前调用 `normalizeMath`；同时为 `\(...\)` / `\[...\]` 增加占位符保护，避免内部 `* _` 被 markdown-it 转义。
- **手写 SVG（v1.110/决策 31 增补）**：markdown-it 开启 `html:true` 透传 + DOMPurify `USE_PROFILES: { html: true, svg: true, svgFilters: true }` 消毒——Markdown 中手写的 `<svg>…</svg>` 内嵌图形直接渲染（`<img>` 文件引用路径不变）；`script`/`iframe`/`on*` 事件属性/`javascript:` URI 仍被剔除；修改消毒强度改 sanitize 选项，切勿关闭。
- v1.75：`normalizeMath` 组合链新增 `normalizeBareMath`，兜底 LLM 输出的**裸 Unicode 数学**（无 `$` 定界，如 `Λ^n V` 来自 key_points 总结）；规则保守（数学字符起始、括号/花括号配对、含 `^`/`_` 或 ≥2 个数学相关字符才包裹），避免误伤正文；`e^{iξx}` 这类孤立花括号不包裹，防止 KaTeX 报错。
- 修改：新增定界符规则改对应函数并补 `frontend/tests/math.test.ts` 用例；提示词侧已要求模型输出标准 `$...$` / `$$...$$`（`backend/app/ai/prompts/chat.py` §3），新输出走标准路径，归一化仅作兼容兜底。

### 10.4 图谱标签与 tooltip 的 LaTeX/Markdown 渲染（`frontend/src/utils/graphLabel.ts`，v1.79）

- 背景：谱系图节点名（书内知识点常含 `$` 与 `**md**`）、关联原因等多由 LLM 生成，ECharts 原生标签会裸露原文；统一改为「公式渲染为图片 + Markdown 清洗为文本」。
- 公式图片：KaTeX 无 SVG 输出能力，改用 **MathJax tex2svg**（`mathjax-full`，动态 import 按需加载，仅图谱页拉取）把公式转成 SVG data URL，嵌入 ECharts 富文本 `backgroundColor.image`；MathJax 对非法公式输出 `data-mjx-error` 错误 SVG，检测到即回退纯文本。
- 工具函数（`frontend/src/utils/graphLabel.ts`）：
  - `ensureGraphLabelReady()`：一次性预加载 MathJax + KaTeX + markdown-it + DOMPurify（`loadGlobal`/`openIntraBook` 开头 await）。
  - `formulaToImage(latex, fontSize=10)`：LaTeX → `{url, width, height}`（data:image/svg+xml），带缓存；失败返回 `null`。
  - `stripMarkdown(text)` / `splitLabelSegments(raw, fontSize)` / `labelRichFormatter(raw, fontSize, maxChars=12)`：切分「文本段 + 公式段」（支持 `$..$`、`..`、`\(..\)`、`\[..\]`、裸 `\command` 段，单标签最多 2 个公式），**v1.80 起返回 `{ formatter: string, rich }`**：formatter 为「文本直接拼接 + `{fN| }` 公式 token」的字符串，rich 为 token→图片样式表；文本截断加 `…`。
  - **为什么不用对象 formatter（v1.80 修复 `[object Object]`）**：graph 系列 label formatter 若返回对象（`{rich, formatter}` 数组），ECharts 直接把对象写入 zrender `style.text`，zrender 的 `getStyleText`/`parseRichText` 会执行 `text += ''` 字符串化，导致所有节点名渲染成 `[object Object]`；`overflow:'truncate'`/`width` 只是加剧该问题。修复：formatter 只返回字符串，rich 样式表挂到**每个数据项的 `label.rich`**（`GraphView.vue` 的 `data`/`links` 映射中 `label: { formatter, rich }`），系列级 label 只保留 `show/position/fontSize`。边标签（edgeLabel）同样处理。
  - `renderTooltipHtml(src, inline)`：Markdown + LaTeX → 消毒后 HTML（公式占位保护 + markdown-it + KaTeX 内联 + DOMPurify）。
- GraphView 接入点：全局/书内节点 label、全局边 label（`X分 原因`）、tooltip、关联详情/知识点详情弹窗（`<MdRender>`）。
- 修改提示：字号 `LABEL_FONT_SIZE`（默认 10）、文本截断 `MAX_TEXT_CHARS`（默认 12）、公式上限 `MAX_FORMULAS`、ex→px 比例 `MATHJAX_EX_RATIO=0.442`（MathJax font.params.n）；新增依赖 `mathjax-full`（`pnpm add mathjax-full`）。

### 21.2 关键交互流三条（代码调研 2026-08-05）

```text
打开书籍：HomeView 点击卡片 → router 跳转（fullPath 作 key 全量重挂载）→ ReaderView.loadAll 并发拉书籍详情/章节列表/进度

  → 高亮/涂鸦/页图各 composable 并行初始化
```

```text

  → 80ms 节流 flush + 公式未闭合延迟 → stream_key 滚动落库 + 2s 历史轮询补偿 → 消息去重合并
```


### 21.3 核心约定（代码调研 2026-08-05）

- **api 封装约定**：后端统一 `{code, message, data}`，拦截器解包后只返回 data；错误归一为 `Error.message` 供 ElMessage 直接展示；组件内禁止绕过 `src/api/` 直发请求（SSE 流式走 `api/chat.ts` 原生 fetch，属 api 层封装）。
- **后台任务约定**：提交后台任务后 `notifyTaskSubmitted()` 触发任务中心 + `waitForTask()` 等待结果，两步缺一不可（个别入口存在遗漏，新增调用点务必两步齐全）。
- **命名约定**：composables 一律 `useReader*.ts`；utils 纯函数且与 `frontend/tests` 同名文件对应；类型集中于 `src/types.ts`（snake_case 对齐后端）。
- **UI 约定**：emoji 作图标、CSS 变量控主题（`styles/theme.css`）、Element Plus 组件全量引入直接使用。


### 21.4 已知局限性（客观陈述，代码调研 2026-08-05）

1. 测试仅覆盖 utils 纯函数层（vitest 6 个文件），无组件/组合式逻辑/store/api 层测试，亦无 coverage 门禁。
2. 无 i18n 基础设施，全量中文硬编码（约 600~900 条文案）。
3. 无 a11y 基础（可点击 div 无语义、hover-only 操作多处）。
4. 暗色模式仅跟随系统（`prefers-color-scheme`），无手动切换；Element Plus 组件与少量硬编码颜色未纳入变量体系。
5. `router-view :key="fullPath"` 全量重挂载策略与 keep-alive/滚动恢复互斥（query 变化也触发重挂载）。
6. 请求层无取消机制，异步竞态依赖各调用点自觉加序号防护（已有漏网处）。
7. SSE 无断线自动重连（有 2s 历史轮询兜底，属设计取舍）。
8. Element Plus 全量引入（vendor-element chunk 体积大）；mathjax-full 按需加载但体积 MB 级，首次打开含公式图谱有额外下载。
