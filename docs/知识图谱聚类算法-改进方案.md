## 1. 候选方案对比

### 路线 A：术语归一化 + 加权评分 + 图结构聚类（增强现行方案）

- **原理**：在词面共现之上加两层——(a) 别名/归一化表把「同概念异词」折叠为规范词，构造可解释的语义等价层；(b) 语料级 IDF 权重压制高频泛化词；(c) 成簇从「贪心吸收」改为「相似度成图 → 连通分量/社区检测」，消除顺序敏感。
- **适配性**：★★★★★ 纯 Python 零新依赖即可落地；完全继承现行 tag/文件夹优先、post-classify、落盘缓存、词库机制；可解释性（共享术语即边依据）满足谱系图展示需求；数学/LaTeX 文本不受影响（二元组天然跳过公式符号，这一点文档 §10.2 已论证）。
- **成本**：纯计算，12 书毫秒级、300 书预计秒级（两两相似度 O(n²·k)，n=300、k=80 词时约 360 万词对比较，纯 Python <5s）。LLM 仅用于离线生成别名与簇命名，预算宽裕。
- **风险**：别名表错误会引入系统性误合并（需置信度+用户可编辑兜底）；IDF 在书极少时（<10 本）区分度弱（用平滑 + DF 上限缓解）。
- **预期精度**：直接解决 D1~D4；对「近义但完全不同词面」（如「概率论」vs「随机分析」）仍依赖别名表或 LLM，属可管理缺口。

### 路线 B：文本向量化 + DBSCAN/HDBSCAN 密度聚类（用户提示方向一）

- **原理**：书级文本（摘要+目录）embedding → 余弦距离 → DBSCAN(eps, min_samples) 密度连通成簇，噪声点归「其他」。
- **适配性评估（专门结论：改造采纳思想，放弃原样引入）**：
  1. **依赖冲突**：标准实现依赖 sklearn/numpy；纯 Python 手写 DBSCAN 约 80 行（邻域查询 O(n²·d)），n=300 可算，但瓶颈不在算法而在向量来源。
  2. **向量来源两难**：本地模型（bge-small-zh ~100MB）需网络下载，与「网络受限」硬约束冲突，且需 torch/sentence-transformers（非纯 Python）；走用户 LLM API 的 embedding 接口则每次全量重建需 300+ 次调用且不可离线。
  3. **数学文本重灾区**：文档 §10.2/§10.3 已论证预训练中文模型对 LaTeX/公式 OOV 严重，本项目数学书占比高，向量化收益被稀释。
  4. **可解释性丢失**：DBSCAN 只输出簇标签与噪声标签，无法给出「为什么同簇」，与谱系图「显示关联原因」需求（决策 8、验收 9）冲突。
  5. **eps 敏感**：TF-IDF/词集空间高维稀疏，距离分布扁平，eps 难调——这是 DBSCAN 用于文本的公认弱点。
- **采纳方式**：放弃 B 作为主路线；**吸收其两个思想**——(a) 「噪声点」概念 → 相似度低于任何簇门槛的书归「待定/其他」而非强行吸收（现行方案已有雏形）；(b) 若用户未来接受 embedding，仅作第四信号辅助边权（文档 §10.4 讨论倾向一致），以 feature flag 默认关保留接口。

### 路线 C：关键词相似度图 + 社区检测（拓扑聚类，用户提示方向二）

- **原理**：书为节点，两两相似度 ≥ τ 建加权边；用社区检测切分：连通分量（最简）、标签传播（LPA，纯 Python ~60 行、近线性、需 seed 保证可复现）、Louvain（模块度优化，质量最好；networkx 内置 `louvain_communities` 为**纯 Python 实现**，无 C 扩展，网络检索已核实——networkx 本体即纯 Python 包）。
- **适配性评估（专门结论：采纳，作为 A 的成簇引擎）**：
  1. **天然解决 D3**：图是对称构造的，社区划分与节点插入顺序无关（LPA 用固定 seed 排序遍历即可复现）。
  2. **天然解决 D1**：「函数」这种泛化词经 IDF 降权后不再产生边；即使个别弱边存在，社区检测按「内部稠密/外部稀疏」切分，不会像贪心吸收那样滚雪球式吞并 8 本书。
  3. **增量友好**：新书只需与既有节点算边、并入或触发局部重划分；连通分量版本支持「受影响分量局部重算」。
  4. **依赖选择**：自研连通分量 + 加权 LPA 零依赖（合计 <150 行）；若接受 networkx（纯 Python、pip 离线可用 wheel）则可用 Louvain + resolution 参数控制簇粒度，质量上限更高。两者都满足 ADR-010「Python only」。
- **成本**：计算同 A；LPA 迭代一般 ≤10 轮收敛。
- **风险**：LPA 有「大社区吞并」倾向（用加权投票 + 最小簇规模约束缓解）；Louvain 有轻微随机性（固定 seed）。
- **预期精度**：与 A 组合后为最优；单独使用（不解决词面问题）仍会被高频词污染边集，故必须与 A 的术语层/IDF 联用。

### 对比总表

| 维度 | A 术语+IDF+增强 | B 向量+DBSCAN | C 相似度图+社区检测 | **推荐 A+C** |
| --- | --- | --- | --- | --- |
| 纯 Python 零/低依赖 | 零依赖 | 需 sklearn 或自研+向量源 | 零依赖（或 networkx 纯 Python） | 零依赖起步 |
| 离线可用 | 完全离线 | 本地模型需预下载/API 联网 | 完全离线 | 完全离线 |
| 可解释性 | 强（共享术语） | 弱（分数黑盒） | 强（边=共享术语） | 强 |
| 数学文本适配 | 好 | 差（OOV） | 好 | 好 |
| 顺序无关 | — | 是 | 是 | 是 |
| 增量成本 | 中 | 高（向量重算） | 低（局部） | 低 |
| 解决 D1~D4 | 直接 | 间接 | 直接 | 直接 |
| 落地风险 | 低 | 高 | 低 | 低 |

**结论**：主路线 = **A + C 组合**（术语归一化与 IDF 加权解决"输入质量"，图+社区检测解决"成簇结构"）；B 降级为可选向量辅助信号（feature flag 默认关）；LLM 定位为**离线修正层**（别名生成、簇命名、方向证据抽取、打分增强），不进入聚类主循环，与需求 3.4.7「LLM×共现×人工」三信号框架一致。

## 2. 推荐方案详设（A+C 组合）

### 2.1 术语层：别名/归一化

**表结构**（新增 Alembic 迁移）：

```sql
CREATE TABLE term_aliases (
  id INTEGER PRIMARY KEY,
  canonical TEXT NOT NULL,           -- 规范词（多字术语，如「傅里叶变换」）
  alias     TEXT NOT NULL UNIQUE,    -- 别名/变体（「傅氏变换」「fourier transform」）
  source    TEXT NOT NULL,           -- user | llm | auto
  confidence REAL NOT NULL DEFAULT 1.0,  -- auto 来源 <1，供人工复核排序
  created_at TIMESTAMP NOT NULL
);
CREATE INDEX ix_aliases_canonical ON term_aliases(canonical);
```

**词库文件扩展**（`domain_terms.txt`，向后兼容现有两段式）：

```
# 用户自定义区（每行一个术语，最高优先级）
傅里叶变换
# ---- 同义词区（格式：规范词 = 别名1, 别名2）----
傅里叶变换 = 傅氏变换, Fourier变换, fourier transform
变分法 = 变分, calculus of variations
# ================= 系统缓存区（自动追加，可编辑/删除）=================
```

**来源（三路，全部离线/低预算）**：

1. **用户词库**：同义词区手工维护，加载即生效（沿用现有 mtime 缓存机制 lexicon.py:38-66）。
2. **LLM 离线生成**：书归档（`archive_book_task`）时，对该书 RAG 资产的 `summary+key_points` 已抽术语做一次「别名归并」调用（每书 1 次、输入 ≤2k token），输出 `{canonical, aliases[], confidence}` 写入 source=llm；失败静默跳过不阻塞归档。
3. **自动候选**：重建时扫描跨书高频术语对——编辑距离 ≤1 或共享 ≥3 字符且各自 df≥2 的词对 → 作为 confidence=0.5 的 auto 候选落库，并在设置页/词库中供确认；未确认的 auto 别名**只参与边权加成、不参与归一折叠**（防错合并）。

**归一注入点（唯一入口）**：新增 `services/graph/terms.py::canonical_terms(term_freq: dict) -> dict`，把词频字典折叠到规范词（同规范词的词频求和）。注入三处：`assign_clusters` 成图、`_pair_score`、`_posterior_keywords` 之后。`extract_keywords` 本身不改（保持缓存与下游行为冻结），归一是其上的薄层。

**长词优先**：折叠与抽取候选时，词库术语按长度降序做最长匹配（`_lexicon_hits` 已有子串命中逻辑，补「长词命中则抑制其内部二元组权重 ×0.3」），使「傅里叶变换」命中时「傅里」「里叶」不再独立计分——这是簇名从 2 字变多字的词法基础。

### 2.2 相似度/相关性函数

**新评分公式**（替换 `_pair_score`，保留函数签名与返回结构）：

```
# 语料级 IDF（N=书数，df=含该规范词的书数；随书增删惰性重算并缓存）
idf(t) = ln((N + 1) / (df(t) + 1)) + 1
# 泛化词压制：df(t)/N > 0.7 的词 idf 再乘 0.2（不删除，保留弱信号）
# 书级权重向量（归一化词频 × IDF × 来源加权：章节标题 2.0 / 正文 1.0 / RAG 后验 3.0）
W_b(t) = tf_norm(t, b) · idf(t) · zone_weight
# 相似度 = IDF 加权余弦
Sim(a, b) = Σ_{t∈Ka∩Kb} W_a(t)·W_b(t) / (√Σ W_a² · √Σ W_b²)
```

与现行差异：min 型伪余弦 → 真余弦；原始词频 → IDF 加权；词面 → 规范词；「函数」类 df 覆盖 10/12 书的词权重压到 ~1/7，直接解除 D1/D4 的主导词问题。

**建边与阈值体系**（集中到 `services/graph/thresholds.py` 常量，替代散落魔法数）：

| 阈值 | 初值 | 作用 | 替代现状 |
| --- | --- | --- | --- |
| τ_edge | 0.06 | Sim ≥ τ_edge 且共享规范词 ≥2 才建「概念共现」边 | score≥1.0 |
| τ_cluster | 0.10 | 聚类图边门槛（高于建边，簇更紧） | Σmin≥2 |
| τ_post | 3 → 改为 Sim_post ≥ 0.15 | post-classify 归属校验 | T_POST=3 |
| τ_merge | 簇代表向量 Sim ≥ 0.35 | 簇合并 | T_MERGE=5 词重叠 |
| 同簇补边 | strength = 5 + 10·Sim | 低分「主题相似」边 | 固定 8 |

全部阈值保留「画像自动学习覆盖」钩子（沿用 profile_learning 的 related_strength 机制），初值用 §4 评估集标定。

**LLM 打分增强**（`llm_score.py` + `graph_edge.py` 重写 prompt）：

- **输入加厚**：每本书给 LLM：清洗后书名、作者、出版年（若 2.6 已落地）、目录前 20 章标题、RAG 摘要 ≤200 字（无资产则用前 3 章标题）；再附两书共享规范词 top10。预算不变（仍 MAX_LLM_PAIRS=40，输入 ~1.5k token/对）。
- **输出加 evidence 约束**：`{"strength", "from_book", "direction", "relation_type", "evidence": ["必须引用所给目录/摘要中的具体词或章节名，≥2 条"], "reasons": [...]}`；evidence 引用不到所给材料的输出判为解析失败 → 回退关键词分（抑制 D5 臆测）。
- **允许降分**：`apply_llm_result` 从 `max` 改为融合：`strength_final = round(0.4·kw + 0.6·llm)`（LLM 可把虚高边拉下来）；但 `user_feedback=确认` 的边冻结不降。这是行为变更点，列入 §6 开放决策。
- **双向校验（可选开关）**：仅对融合后 ≥60 的高分对交换 A/B 位置复评一次，两次 direction 矛盾则降为「无」；增量约 ≤15 次调用/次重建。
- **方向输出仅作为候选**：最终方向由 2.6 锚点链裁决，LLM 不再一票定方向。

### 2.3 领域聚类算法（替换贪心吸收）

**流程**（`assign_clusters` 领域聚类段重写，tag/文件夹/post 优先级链不变）：

```
输入：待领域聚类书集合 P（无 tag/文件夹/post 失效）
1. 特征：每书 canonical_terms(book_keywords(b, 80)) → IDF 加权向量 W_b
2. 成图：两两 Sim ≥ τ_cluster 建无向加权边；孤立点暂挂「其他」
3. 成簇（二选一，见开放决策 O1）：
   a) 连通分量（零依赖基线）：边集上的并查集；
   b) 加权标签传播（零依赖增强）：
      labels = {b: b}; 固定 seed 排序遍历
      labels[v] = argmax_c Σ_{u∈N(v),label(u)=c} Sim(u,v)
      平局取簇规模大者；迭代 ≤10 轮或无变化；
      后处理：簇规模 < MIN_CLUSTER(=1) 保持；
      防吞并：节点改标仅当新簇权重和 > 当前簇权重和 ×1.05
4. 大簇分裂守卫：簇内平均两两 Sim < τ_cluster ×0.8（"虚胖簇"，
   即现行 8 书「函数」的形态）→ 对该簇递归执行步骤 2~3（子图重切）
5. 命名（见 2.4）→ 落盘 + 缓存
```

伪代码对应约 120 行纯 Python；并查集 + LPA 均无外部依赖。**顺序敏感问题（D3）由此根除**：图构造对称、遍历序固定为 book.id 升序 + seed。

**增量更新策略**：

- 新书导入（`incremental_cross_book_graph`）：只算新书与既有书的 Sim；若 max Sim ≥ τ_cluster → 并入最佳簇（更新该书落盘）；否则视其为种子看能否吸附其他「其他」书（仅局部两两，不回卷已定簇）；全程不重算全库。
- 归档/资产升版：该书走 post-classify 校验（2.2 τ_post），迁簇只改该书落盘；触发一次**受影响簇**的 merge 检查（`merge_and_rename_clusters` 缩为「该书新簇 vs 相邻簇」而非全量两两，解决现行 O(簇²) 全扫描）。

**缓存失效粒度**（解决 D11）：缓存键从「全库群体签名」改为分层：

```json
{
  "algo_version": 2,
  "lexicon_sig": "<词库+别名表 mtime/内容哈希>",
  "idf_sig": "<书数+df 表哈希>",
  "books": {"<book_id>": {"sig": "<现行单书签名>", "cluster": "…"}}
}
```

- 单书签名变化 → 仅该书重判（增量路径）；
- `lexicon_sig`/`idf_sig`/`algo_version` 变化 → 全量重算（词库编辑属低频显式操作，可接受）；
- 全量重建入口（`POST /rebuild`）保留强制刷新。

### 2.4 簇命名

**多字候选生成**（改造 `_domain_candidates`）：

1. 词库术语命中（用户区 > 缓存区，权重 100，现行保留）；
2. **章节标题 n-gram（n=2~4 字）**：连续汉字串按 n=4,3,2 滑窗，只保留在 ≥2 个章节标题复现的 n-gram（如「傅里叶分析」），权重 30×n/2——多字优先；
3. RAG 后验 key_points 标题中的名词短语（经 2.1 归一），权重 50；
4. 二元组仅作兜底，权重 1。

挑选规则不变（覆盖书数优先 → 权重和），但**候选最小长度 = 3 字**（2 字仅当无任何 ≥3 字候选时兜底），泛化词过滤表沿用并扩充。

**LLM 命名（质量门槛触发）**：簇满足「成员 ≥2 书 或 候选最高权重 <60」时发起 1 次命名调用：输入簇内每书清洗书名 + top5 章节标题 + 候选词列表，输出 `{"name": "≤8 字领域名", "confidence": 0~1}`；`confidence ≥0.7` 采纳并写入系统缓存词库，否则回退规则候选。预算：簇数 ≪ 书数（300 书预计 20~40 簇），每次重建 ≤40 次命名调用，与打分预算同量级，用户已确认「命名类预算宽裕」。重命名去重沿用现行 used_names 冲突跳过。

### 2.5 跨书脉络：方向锚点与边类型

**客观锚点链（direction 裁决优先级）**：

1. **出版年（新增字段，首要锚点）**：`books.published_year INTEGER NULL` + `pub_year_source`（filename/llm/user）。获取：导入时正则解析文件名/书名中年份（`(20\d{2}|19\d{2})`、第 N 版）→ 归档时 LLM 单次抽取（输入书名+作者+目录前 10 章，输出 JSON，每书 1 次、结果落盘不重复调用）→ 书详页可手改。裁决：年份差 ≥3 年且有传承类 relation_type → 方向 = 早者 → 晚者（承接/发展由 LLM 类型给出）；年份矛盾 LLM 方向 → 以年份为准。
2. **目录结构包含度**：`TOC_inc(A→B) = |规范词(A目录) ∩ 规范词(B正文)| / |规范词(A目录)|`；A 目录术语 ≥60% 出现在 B 正文且 B 目录几乎不含 → A 是工具/基础书（如线性代数 → 傅里叶分析），支撑「应用扩展」方向。纯词面可算、零成本、可解释。
3. **LLM 结构化抽取（现行增强版）**：仅当 1/2 无结论时采用，且要求 evidence（2.2）。
4. 三者均无 → direction=「无」（宁缺勿造，纠正现行 10/33 边全靠猜的状态）。

**边类型体系**（`RELATION_TYPES` 扩展 + 语义收紧）：

| 类型 | 判定依据 | 方向性 |
| --- | --- | --- |
| 理论传承 | 出版年序 + LLM evidence 明确师承/体系继承 | 有向 |
| 前置基础 | TOC_inc 锚点命中（A 是 B 的工具书） | 有向 |
| 应用扩展 | B 正文高频使用 A 的核心术语但目录无 A 主题 | 有向 |
| 概念共现 | 共享规范词 ≥2、Sim ≥ τ_edge，无锚点 | 无向 |
| 主题相似 | 同簇补边 | 无向 |
| 并列参考 | 同领域同年段、互不包含 | 无向 |

现行 33 条边全部可通过重建迁移（relation_type 白名单校验已有，扩充即可）。

### 2.6 书内脉络（intra_book.py 重构）

**三层归属边（解决 D7）**：建图时补 `relation_type="归属"` 边：重要段落 KP → 其章节级 KP（strength=100）；用户标记 KP → 其章节级 KP。前端 intra 视图按 level 过滤时归属边同步显隐（已支持边过滤，零结构改动）。

**逻辑依赖判定（替换位置序，解决 D8）**，三信号叠加：

```
1) 章节引用（正则，零成本）：正文命中 r"(参见|见|回顾|由)\s*第?\s*([0-9一二三四五六七八九十]+)\s*[章节]"
   → 当前章 KP → 被引用章 KP，「前置依赖」strength=80，note="正文引用第X章"
2) 术语前置（词面，零成本）：章节 c_j 的规范词集含 definitional(c_i)
   （c_i 中以「定义/定义"/Definition」句式引入的术语，沿用 _THEOREM_RE 扩展），
   且 i<j → c_i→c_j「前置依赖」strength=40+20·重叠术语数（上限 90）
3) LLM 校验（归档时、抽样、可关）：取术语共现最高的 ≤8 对章节对，
   输入两章标题+各 3 个 key_points，输出 {prerequisite: A/B/none, reason}
   确认的边 strength=90、note 附 reason；预算 ≤8 次/书归档，仅归档触发一次
```

现行「章节顺序」边降级保留为 `relation_type="阅读顺序"`（strength=20，前端浅色虚线），不再冒充逻辑序——阅读顺序本身有展示价值，删除会损失信息。

**重要段落提取改进（解决 D9）**：

```
候选打分（规则，全量执行）：
  score = 2.0·_THEOREM_RE 命中 + 1.5·Markdown 加粗/标题行 + 1.0·长度∈[20,300]
        + 1.5·规范词密度(该章 top 词命中率) − 2.0·表格行(|开头)/列表行(- 开头)惩罚
  每章取 score top-K（K=5）为候选
命名（两段）：
  规则：候选行中提取首个加粗段/引号术语/「X 的定义|定理」模式 → 概念名 ≤20 字
  LLM（归档时批量，每书 1 次调用）：输入每章候选行（≤30 行/书），
  输出 [{para_pos, concept_name(≤20字), one_line_summary(≤50字)}]
  → title=concept_name，summary=原行前 300 字，importance=5
  LLM 失败 → 回退规则命名（title 用清洗后行首 20 字，去 Markdown 符号）
```

## 4. 验证方式

**人工评估集（P0 建立，持续扩充）**：

- **书级金簇**：当前 12 书人工标注（建议金标：变分法{4,8}、概率统计{7}、阅读{…}、金融{17,18}、分析学下细分 傅里叶{13}/线性代数{15}/微积分{19,21}/方法论{12}、图形或哲学{20} 单独）；每新增 10 本补标一次，目标 30 本。
- **对级标注**：33 条现存边全标（强度区间+方向对错）+ 随机 20 条未建边书对（查缺：漏边率）。

**聚类质量指标（纯 Python 实现，`test_cluster_eval.py`）**：

- 簇纯度与 pair-F：`pair-F = 2·TP/(2·TP+FP+FN)`，TP=同簇且金标同簇的书对——对「8 书挤函数」最敏感的指标；
- **轮廓系数纯 Python 近似**：基于 2.2 的 Sim 矩阵，`s(i)=(b_i−a_i)/max(a_i,b_i)`，a_i=同簇平均 Sim、b_i=对其他簇最小平均 Sim，O(n²) 直接实现，300 书 <1s；
- 簇名质量检查表（自动）：长度 ≥3 字、不在泛化词表、无标点、无重复；
- 顺序稳定性测试：同批书 3 种导入顺序跑聚类，断言结果完全一致（现行必然失败，P2 后必须通过）。

**回归对比清单（每阶段）**：`global_graph_payload`/`intra_graph_payload` 字段 diff（只增不删）；tag/文件夹/post 优先级链用例；`tests/test_graph.py`、`test_graph_incremental.py`、`test_graph_llm_score.py`、`test_relatedness.py`、`test_perf_tier1.py`（聚类缓存命中）全绿；性能断言：300 书模拟数据全量聚类 <30s（ADR-010 红线）；未配置 AI 时零 LLM 调用。

- tau=0.15 / 0.20：独立成簇，命名层注入命中「自然种类 / 形而上学 / 实在论」→ 簇名**自然种类**（哲学）→ 命中「哲学」验收 ✓；
- 对照 A 现行贪心：任何 tau 下 20 都被吸进 8 书数学大簇（D1 复现，无法验收）。

**成簇结果（tau=0.15, bloat=1.2）**：概率论{7}、变分法{8}、收敛{12,13,21}、线性代数{15}、金融数学{18}、因果{16}、固定收益{17}、微分{19}、自然种类{20}；纯度 0.926、最大簇 3、单点簇 8。

**结论**：
1. **两层分离有效**：聚类输入无注入词干扰；命名层正确识别哲学书（自然种类）；LaTeX/SVG 记号（mathbf/text/fill/stroke…）已入 `_GENERIC` 排除，簇名质量提升（15：mathbf→线性代数、18：金融数学）；
1.1 **领域名一律中文（用户定稿 2026-08-05）**：命名候选剔除纯 ASCII/记号 token，`固定收益` 规范词改为 `金融`（fixed income → 金融，`backend/domain_terms.txt` 同步、.example 增示例行）——17 号书簇名 rate→**金融**；注入抑制规则修正为「仅压命中词内部 token」（原 `c in t` 方向误伤：命中「金融」把「金融数学」压到 0.3，导致 18 号书被误命名「复变函数」→ 修正后恢复「金融数学」）；
2. **分裂守卫 bloat 敏感性**（demo 参数，正式版 `BLOAT_FACTOR=0.8`）：0.8/1.0 不触发——「枢纽链」形态（12/13 为枢纽把 18/21/15 粘连，簇内平均 Sim=0.164 ≥ τ×0.8）不被平均判据识别；1.2 触发并分裂出 线性代数{15}、金融数学{18}，纯度 0.886→0.926、簇数 7→9；建议正式版默认保留 0.8 并开放配置/按簇规模自适应（见 §6 O9）；
3. **词面天花板**：金标对 (17,18)（英文 vs 中文金融书）与 (19,21)（SVG/LaTeX 噪声词面无交集）无法仅靠关键词命中同簇 → pair-F recall 上限 0.5（tau=0.10 已达）→ 印证「LLM 离线修正层 + 用户 tag」为必选兜底；
4. **PDF 关键词质量是最大瓶颈**：真实库 PDF 书关键词为字级二元组（茆诗/率论）与 LaTeX/SVG 记号，术语层折叠对其无效（同义词开/关指标完全相同）→ 正式版应在 RAG 文本层（视觉提取缓存 / 全文）上抽取关键词（关联决策 36 附件文本化路径），或将 jieba 提上 P2 议程（§6 O2）。

## 5. DBSCAN 与拓扑聚类评估结论摘要

用户提示的两个参考方向均已做专门评估（完整论证见 §1 路线 B / 路线 C），结论如下：

**DBSCAN（路线 B）：放弃原样引入，吸收其思想**。五点原因：

1. **依赖冲突**：标准实现依赖 sklearn/numpy，纯 Python 手写虽可行，但瓶颈不在算法而在向量来源；
2. **向量来源两难**：本地 embedding 模型需联网下载且依赖 torch/sentence-transformers（非纯 Python），走 LLM API embedding 则不可离线且调用量大；
3. **数学文本 OOV**：预训练中文模型对 LaTeX/公式覆盖差，本项目数学书占比高，向量化收益被稀释；
4. **可解释性丢失**：DBSCAN 无法给出「为什么同簇」，与谱系图「显示关联原因」需求冲突；
5. **eps 敏感**：高维稀疏词集空间距离分布扁平，eps 难调。

**吸收方式**：(a) 「噪声点」思想 → 相似度低于任何簇门槛的书归「待定/其他」而非强行吸收（§2.3 孤立点处理）；(b) embedding 仅作未来可选第四信号，feature flag 默认关（开放决策 O7）。

**拓扑聚类/社区检测（路线 C）：采纳，作为 A 的成簇引擎**。天然解决 D1（泛化词降权后不再滚雪球吞并）与 D3（图构造对称、顺序无关），增量友好；零依赖自研（连通分量 + 加权 LPA）或 networkx Louvain（纯 Python，符合 ADR-010）二选一，见开放决策 O1。注意：必须与 A 的术语层/IDF 联用，否则边集仍会被高频词污染。
