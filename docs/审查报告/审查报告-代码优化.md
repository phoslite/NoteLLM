### 2.1 P0 分层违规（§5）

#### P0-1 services 层直接拼原生 SQL 文本
- **文件**：`backend/app/services/search_service.py:40-48`（LIKE 回退查询）、`:78-88`（FTS5 MATCH 查询）
- **问题**：两段 `text("SELECT ... FROM ... JOIN ...")` 原生 SQL 字符串直接写在服务层，是 §5「services 直拼 SQL」的最典型形态（§2 过度耦合信号明确点名）。
- **解决方法**：新建 `repositories/search.py` 承载 FTS/LIKE 查询，服务层只做关键词拆词与结果组装（提取公共方法）。

#### P0-2 路由内联业务逻辑：图谱人工反馈
- **文件**：`backend/app/api/routes/graph.py:148-172`（`relation_feedback`）、`:79`（懒构建判断）
- **问题**：路由直接 `db.get(BookRelation)` 后按 `"确认"/"忽略"/"修改"` 分支改模型字段并 `db.commit()`——完整业务规则（含强度 Clamp `max(0.0, min(100.0, ...))`）内联路由；`:79` 路由直查 `db.query(BookRelation).count()`/`db.query(Book).count()`。
- **解决方法**：反馈写入下沉 `services/graph_sync.py` 或新建 `graph_feedback` 服务；懒构建判断提取为服务层 `needs_build(db)`。

#### P0-3 路由直构 LLM 客户端 + 内联连接测试业务
- **文件**：`backend/app/api/routes/settings.py:9`（import LLMClient）、`:108-117`（`_run_connect_test` 直接 `LLMClient(**kwargs, kind=kind)` 并发起 ping）
- **问题**：§5 要求 LLM 客户端经工厂/注入；路由层不应承载「发起最小对话验证连通性」业务。
- **解决方法**：抽 `services/settings_service.test_connection(db, kwargs, kind)`，客户端构建走 `ai/factory.py`。

#### P0-4 路由直连仓储做业务编排：chat 缓存回放
- **文件**：`backend/app/api/routes/chat.py:64-83`
- **问题**：缓存命中回放路径在路由内做转义清洗（`:66` 自写 `.replace('\\"', '"')`，与 `chat_service._sanitize_answer` 重复）并直调仓储 `persist_chat`——同一文件的流式路径已收敛到服务层，回放路径漏收敛。
- **解决方法**：提取 `chat_service.replay_cached_answer(...)`，清洗复用 `_sanitize_answer`。

#### P0-5 路由内联业务计算：阅读进度
- **文件**：`backend/app/api/routes/reading.py:58`（路由 `db.get(Chapter, ...)` 直查模型）、`:90-96`（整书进度公式 `(idx + position) / total` 内联路由）
- **问题**：模型直查与业务公式计算都在路由层。
- **解决方法**：章节归属校验下沉仓储（提供 `get_chapter_of_book`）；进度计算下沉 `repositories/reading.update_book_reading` 或独立纯函数。

#### P0-6 路由内联文件持久化：涂鸦标注
- **文件**：`backend/app/api/routes/annotations.py:24-41`（路径约定 + JSON 读取）、`:63-65`（mkdir + 覆盖写盘）
