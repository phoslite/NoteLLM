## 1. 背景与目标

代码审查发现：**图谱链路**（懒构建 / 重建 / 联动 sync）与**导入链路**（同步解析 + 页图渲染 + 增量图谱）都在请求内同步执行，且多处 LLM 调用串行，书多 / 文件大时阻塞数秒~数十秒且无进度反馈。

目标（对应 需求-决策 9.3 第 1/2/8/9 项）：

1. 所有耗时操作后台化：上传秒回、任务带 `progress(0~100)` / `stage`、前端进度条；
2. 热点计算与 LLM 调用并行化：页图渲染、视觉全书提取、跨书 LLM 打分、图谱联动增改；
3. 前端无依赖请求并行化，缩短页面加载与操作体感；
4. 全程不引入新语言 / 新服务 / 新向量检索（ADR-010 / ADR-011 一致）。

## 3. 改造原则与边界

- **本地单用户**：不做分布式 / 消息队列；应用内线程池 + 信号量即可（ADR-010）。
- **任务系统为全局基础**：所有落点（1~9）统一收敛到升级后的 `tasks`（落库、线程池、同类型配额、progress/stage、状态查询、失败回滚不阻塞）。
- **LLM 并发限流**：全局信号量，文本 / 视觉分池（demo 实测文本 4、视觉 4~8 为甜点）；同类型任务全局配额，超出排队。
- **数据库**：SQLite WAL 已启用（读并发 / 写串行）；任务内独立 `SessionLocal`；写冲突重试或顺序化。
- **保留串行硬依赖**：归档链路「视觉通读 → 文本总结」保持串行；页级进度原子回填；单页 / 单对失败不中断整体。
- **降级**：LLM 调用失败一律回退原规则结果（关键词分 / 现有行为），不阻塞功能。

## 5. 验收标准

1. 导入大 PDF（≥50MB）：上传秒回 `task_id`，前端可见任务卡片进度条（解析 / 页图 / 增量图谱阶段文案），期间书架与阅读可正常操作；
2. 首次打开谱系图不阻塞请求：后台构建 + 前端轮询；重建 / 联动按钮有进度反馈；
3. 视觉全书提取实测提速（4~8 并发），页级进度原子回填，单页失败不中断；
4. 跨书 LLM 打分与图谱联动并发执行，失败对回退关键词分，行为与串行版一致；
5. 测试连接不阻塞设置页（后台任务 + 轮询）；
6. 前端 `ProfileView` / `RagDetailView` 请求并行；`ReaderView` 打开书体感改善；
7. 回归：后端 pytest 全绿、ruff 全绿、vue-tsc + vite build 通过；任务重启后状态不丢（落库）。

## 6. 风险与注意事项

- **SQLite 写并发**：WAL 读并发、写串行；多任务并发写时可能 `database is locked` —— 写操作顺序化 / 短事务 / 重试。
- **LLM API 限流**：全局信号量 + 配额防额度争抢；并发数按 demo 实测取甜点。
- **任务状态落库**：新增表走 alembic 迁移；旧内存态任务兼容（读不到视为失败或迁移）。
- **线程安全**：每个任务独立 Session；共享状态（进度）用线程安全容器。
- **前端轮询开销**：进度轮询限频（如 1s）；任务结束自动停止。
- **行为等价**：并发改造不得改变既有结果（打分取 max 语义、失败回退、幂等增量）。
